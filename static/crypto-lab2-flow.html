crypto-lab2 — Trading System Flow

atlantide-crypto-lab · Hybrid Scoring + Candlestick Pattern Scalp · 15m timeframe · loop every 1s

Step-by-Step Execution Flow

PHASE 1 Data Collection (every 1s)

1
WebSocket stream pushes 15m candle closes
Binance WebSocket delivers real-time 15m and 5m candles for 20 active symbols (60 total streams). Each closed 15m candle is appended to candles[sym]["15m"]. Ticker prices, highs, lows, volumes updated in shared state.
→ Ticker prices, highs, lows, volumes updated in shared state
2
Market data bootstrap (on startup only)
On first launch, REST API fetches 100 historical 15m candles per symbol. Gives enough data for EMA(50) + ATR(14) + RSI(14) calculations immediately.
Impact: Without this, strategy cannot run until ~12 hours of candles accumulate naturally.

PHASE 2 Strategy Evaluation (every 1s, per symbol)

3
compute_indicators() — Technical Analysis
From 30 closed 15m candles, calculate: ATR(14) for SL distance, RSI(14) for overbought/oversold (thresholds tightened: oversold=25, overbought=75), MACD(12,26,9) histogram for momentum, EMA(9) and EMA(21) for crossovers, EMA(20) for trend direction, EMA(50) for longer-term trend filter. Volume SMA(20) for volume spike detection. Volatility classification (low/normal/high) via ATR percentile over 50 periods.
Impact: RSI thresholds changed from 30/70 to 25/75 — fewer but higher-quality reversal signals reach the scoring engine.
→ indicators[sym] dict populated for display and downstream scoring
4
Trend Cross-check (Price-vs-EMA20) — NEW
After computing the EMA20 slope-based trend classification, perform a cross-check: if the close price is on the WRONG side of EMA20 (e.g., "uptrend" flagged by slope but close is BELOW EMA20), downgrade the regime to "ranging". This prevents the regime direction filter from blocking correctly-directioned trades when the EMA20 slope is lagging price action.
Impact: Prevents false trend classifications from blocking valid trades. The EMA20 slope can lag significantly after sharp reversals — this cross-check catches that and defaults to "ranging" which lets both directions through the regime filter.
5
Candlestick Pattern Detection
Scan last 3 closed candles for: Hammer (long lower wick ≥ 1.5×body, tiny upper wick → LONG, REQUIRES preceding downtrend — checks slope over last 3 candles), Shooting Star (long upper wick ≥ 1.5×body, tiny lower wick → SHORT, REQUIRES preceding uptrend), Engulfing (current body fully engulfs previous body ×1.5 → direction of engulf), Doji (body <10% of range → skip pattern). Wick ratio tunable by self-learning (1.2–4.0). Engulfing min body ratio tightened from 1.3 to 1.5.
Impact: Reversal patterns (Hammer/Star) now require confirming preceding trend — prevents false reversals in ranging markets. Previously they fired on any candle shape match regardless of context.
6
score_entry() — Multi-Signal Aggregation
Sum weighted scores from ALL active signal types into a total score (−8.85 to +8.85 range):
Hammer: +2.5 · Shooting Star: −2.5 · Engulfing: ±2.0 · EMA Cross (fresh): ±2.0 · EMA Position (no cross): ±1.0 · RSI Bounce: ±1.0 (scaled ×1.0–1.3) · MACD Histogram: ±0.5 (scaled ×0.5–1.5) · Volume Spike: ±0.3 (directionless, amplifies existing bias)
Impact: Pure-indicator entries (RSI, MACD, Volume) weighed lower to prevent noise-driven trades from crossing threshold. Candle patterns and EMA cross dominate the score.
7
Candle Pattern Dominance Check
If the strongest signal is a candle pattern (Hammer/Star/Engulfing) but total score points the OPPOSITE direction → total score penalized by 70% (×0.3). This prevents conflicting signal pollution — e.g. a Hammer (+2.5) accompanied by conflicting negative signals (−3.0 total) gets crushed to −0.9.
Impact: Candle pattern direction must reinforce the aggregate, not fight it. Applied BEFORE entry threshold check.
8
Entry Threshold Check
If abs(total_score) >= entry_threshold (tunable 2.0–6.0, default 3.5) → signal passes to downstream filters. Otherwise → signal discarded.
Impact: Threshold reduced from 4.0 to 3.5 — the 4.0 setting was too aggressive for low-volatility range markets and blocked nearly all signals. 3.5 balances signal quality with sufficient trade frequency across market regimes. Self-learning tunes this after every review cycle (±5% change per cycle).
9
Regime Direction Filter (normal vol ONLY)
Downtrend + normal volatility → ONLY SHORT passes (returns None for LONG). Uptrend + normal volatility → ONLY LONG passes. Ranging → both directions allowed. This is a FULL BLOCK (returns None). REVISED: now only applies in 'normal' vol — in high/low volatility regimes, the short-term EMA20 trend is unreliable, so the regime filter is skipped and the EMA50 anti-trend filter handles blocking. The Price-vs-EMA20 cross-check (step 4) additionally prevents mis-classified trends from blocking valid trades.
Impact: Reverted from "all vol" back to "normal vol only" because high/low vol trends are unreliable. The EMA50 filter (2h timeframe) is much more robust for trend detection in stress markets.
10
TP/SL Calculation
SL: entry ± 2.0 × ATR(14) on 15m timeframe. Clamped to candle pattern range so SL cannot be placed absurdly far. TP: entry ± (SL_distance × RR_RATIO) where RR_RATIO = 1.5. RR ratio is FIXED at 1.5 — no longer tunable by self-learning.
Impact: Wider SL (2.0× ATR) reduces false stop-outs. Tighter RR (1:1.5 vs 1:2) increases TP hit rate. Together these improve the win rate / expectancy balance.
→ signal_state[sym] set: signal=LONG/SHORT, tp, sl, score, entry_type, trend, vol_label
11
Anti-Trend Filter (EMA50 slope ~2h) — FULL BLOCK
If EMA50 slope over 8 periods (~2 hours) is bearish but signal is LONG → signal BLOCKED entirely. If EMA50 is bullish but signal is SHORT → signal BLOCKED entirely. Requires 58+ data points to activate. This is now a FULL BLOCK — the old ×0.5 penalty was applied after the threshold check, making it completely ineffective (trades passed through with only a position-sizing penalty). Now returns None, completely preventing anti-trend trades.
Impact: Medium-term trend overrides the signal completely. Much stronger protection against trading against dominant 2h direction. In high/low volatility, this is the primary trend filter since the regime filter is bypassed.

PHASE 3 Risk Filters & Execution (every 1s, per symbol)

12
Cooldown Check
If time since last trade close on this symbol < 15 minutes → skip. Prevents rapid re-entry after a loss.
Impact: After a losing trade, system waits 15 min before considering the same symbol.
13
Consecutive SL Pause
If symbol hit 5 consecutive stop losses → pause for 1 hour. Counter resets on any TP or TRAILING close.
Impact: Per-symbol circuit breaker. Stops the system from bleeding on a particular asset. Counter tracked in consecutive_sl_losses[sym].
14
Open Positions Loss Filter
If 50%+ of all open positions across ALL symbols have negative unrealized PnL → skip opening new trades. Requires at least 2 open positions to activate (a single losing position is normal price noise).
Impact: System-wide guard. Prevents stacking losses when multiple positions are underwater.
15
Global 3-Loss Suspension ← FINGERPRINT GUARD
If the last 3 closed trades across ALL symbols are ALL losses → suspend all new entries for 3 hours. FINGERPRINT GUARD: Records suspension_fingerprint = len(closed_trades) at trigger time. Uses strict > comparison — same set of trades can never trigger a suspension twice. Existing open positions continue resolving during freeze. On expiry, fingerprint advances past current trade count to prevent re-trigger.
Impact: Aggressive cooling-off (3h) to prevent re-entry into unfavorable conditions. Fingerprint prevents re-trigger loop on expiry.

PHASE 4 Trade Opening & Monitoring

16
Position Sizing
Base risk = 10% of per-symbol capital. Adjusted by confidence multiplier (score 3.5–5.0 → 0.75×, 5.0–6.5 → 1.0×, 6.5+ → 1.5×). Volatility multiplier (high vol → 0.5×, low vol → 1.2×). Final notional = risk_amount / SL_distance_pct. Margin capped at 2× available balance. Leverage = 5×. Max 1 open trade per symbol.
Impact: Only 1 open trade per symbol. In high volatility, position size halves.
17
Open Trade — Record to State + DB
Trade dict appended to open_trades[sym]. Includes: id, entry price, direction, TP, SL, notional, margin, entry_fee, risk_amount, confidence_mult. SL is recomputed from live entry price using 2.0× ATR (not the signal's projected SL from candle close). TP derived from SL distance × 1.5 RR. last_entry_signal set to prevent re-entry on same signal. State saved to SQLite. Conditions snapshot captured.
→ state saved to atlantide.db · SSE broadcast to dashboard · conditions snapshot
18
Monitor Open Trades (every 1s)
For each open trade: update unrealized PnL from current price. Check TP hit → close. Check SL hit → close. Check trailing stop: activates at 35% of TP distance, trails at 35% behind price extreme, capped at breakeven — never lets trailing SL go below entry for LONG or above entry for SHORT. TRAILING label only applies if the close is actually profitable (prevents labeling gap-through losses as "trailing").
Impact: Earlier activation (35% vs 50%) locks in profits sooner. Tighter trail captures more gain. Breakeven cap guarantees trailing stops never turn winners into losers.
19
Trade Close — PnL & Capital Update
Gross PnL = (exit−entry)/entry × direction × notional. Deduct entry_fee (0.05%) + exit_fee (0.05%). Update per-symbol capital: balance, total PnL, win/loss counters, peak, max drawdown. Consecutive SL counter incremented on SL closes, reset on TP/TRAILING. Trade scored + conditions snapshot captured. Trade close time recorded for cooldown.
→ closed_trades[] append · SQLite INSERT · SSE broadcast · Self-learning trigger · Conditions snapshot

PHASE 5 Self-Learning (reviews every 10 new trades / 60s loop)

20
Compute Performance Metrics
Sharpe ratio, profit factor (gross_win/gross_loss), win rate, avg win/loss, expectancy, max drawdown. Per-entry-type breakdown: count, wins, PnL, win rate for each of HAMMER, SHOOTING_STAR, ENGULFING, EMA_CROSS, RSI_BOUNCE, MOMENTUM. Goal progress: Sharpe (target 1.5), Win Rate (target 40%), Monthly Return (target 10%), Max DD (limit 20%).
21
Diagnose & Tune One Parameter
IF any entry type has <25% win rate after 5+ trades → raise entry_threshold. ELIF win rate <28% + PF<1.0 → raise entry_threshold. ELIF win rate ≥40% but PF<1.5 → increase risk_pct. ELIF win rate <32% + PF<1.0 → raise wick_ratio. ELSE cycle to next param. Change by 5% per iteration. If param stuck at bound → try next param. Oscillation guard: if entry_threshold changed 3+ consecutive times with WR ≤ 5%, force a different parameter.
Impact: Only ONE parameter changes per review. RR ratio REMOVED from tunable params — FIXED at 1.5. Remaining params: entry_threshold (2.0–6.0), wick_ratio (1.2–4.0), risk_pct (5%–20%). Hot-reloadable via active_params[].
22
Forced Review on 5 Consecutive Losses
On every trade close, checks if the last 5 closed trades across ALL symbols are ALL losses. If so, triggers immediate forced review cycle (bypasses the 10-trade interval). Throttled: max once per 10 minutes.
Impact: Catches bleeding streaks in real-time rather than waiting for the next 10-trade review. 10-minute throttle prevents churn.

Signal Types & Weights

  • Hammer (bullish) +2.5 † requires downtrend
  • Shooting Star (bearish) −2.5 † requires uptrend
  • Engulfing ±2.0
  • EMA 9/21 Cross (fresh) ±2.0
  • EMA Position (no cross) ±1.0
  • RSI Bounce ±1.0 (scaled ×1.0–1.3) ↓ 1.5
  • MACD Histogram ±0.5 (scaled ×0.5–1.5) ↓ 1.0
  • Volume Spike ±0.3 (directionless) ↓ 0.5

Risk Filters (in order)

  • Cooldown: 15 min per symbol
  • Consecutive SL: 5 → 1h pause
  • Open Loss: ≥50% of 2+ losing → skip
  • 3-Loss Suspension: 3 losses → 3h freeze
  • Fingerprint guard prevents re-trigger
  • Regime Filter: normal vol only (not all vol)
  • Trend Cross-check: price-vs-EMA20 guard
  • Anti-Trend: EMA50 → FULL BLOCK (was ×0.5)
  • Trailing: 35% activate, 35% trail (was 50%)

Self-Learning

  • Reviews every 10 trades / 60s
  • entry_threshold: 2.0–6.0
  • wick_ratio: 1.2–4.0
  • risk_pct: 5%–20%
  • 5% change per cycle (was 10%)
  • RR ratio: FIXED 1.5 (was 2.0)
  • Forced review on 5-loss streak
  • Oscillation guard after 3× same param
  • Hot-reloadable via active_params[]
